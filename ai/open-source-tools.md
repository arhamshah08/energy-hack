# Open-source tools, one per line

Free tools for the hack, credited to their creators. Check each license before reusing code. Built one of these? Request changes: https://forms.gle/k1pnQ4dtvfcGkuGK6 or email arhams@stanford.edu

## Try in the browser, no install

- **Load Flow Simulator (browser)** by Adjie Brotosukmono: Free browser tool: draw a single-line diagram and run AC Newton-Raphson or DC load flow (PyPSA-based), with animated flows. Examples include a 9-bus system, a 20/0.4 kV feeder and an HVDC link. Offers a link for AI agents to open a scenario. (access: open; tracks: 2; id: loadflow-simulator-web) https://tool.adjiebrotots.com/loadflow-simulator/
- **AC Grid Lab (browser AC power flow)** by Dr. Eshan Singh: Browser tool: build a one-line network on a map or diagram and solve AC power flow; starter case is a California-inspired nine-bus network with voltage and line-loading checks. JSON import and export. (access: open; tracks: 2; id: ac-grid-lab) https://www.eshansingh.xyz/acopf/
- **ED/UC Simulator: economic dispatch and unit commitment (browser)** by Adjie Brotosukmono: Free browser tool: draw a network, decide which units run hour by hour and read nodal prices (LMP); PyPSA with the HiGHS solver. Examples include a PJM 5-bus case and solar plus battery. (access: open; tracks: 2,3; id: ed-uc-simulator-web) https://tool.adjiebrotots.com/ed-uc-simulator/
- **PyPSA California: interactive grid model (browser)** by Dr. Eshan Singh: Browser app over a PyPSA optimization model of the California grid: configure demand, generation, storage, transmission and policy, then solve. No install. (access: open; tracks: 2,3; id: pypsa-ca-app) https://www.eshansingh.xyz/PyPSA-CA/app/

## Power flow and grid simulation

- **pandapower** by Fraunhofer IEE and University of Kassel: Python power flow and optimal power flow on pandas tables, with standard test networks. (access: open; tracks: 2; id: pandapower) https://github.com/e2nIEE/pandapower
- **MATPOWER** by MATPOWER team (Ray Zimmerman): MATLAB/Octave power flow and OPF package. Its case format is used by most grid benchmarks. (access: open; id: matpower) https://github.com/MATPOWER/matpower
- **PowerModels.jl** by Los Alamos National Laboratory: Julia package for steady-state power network optimization with many formulations. (access: open; id: powermodels) https://github.com/lanl-ansi/PowerModels.jl
- **OpenDSSDirect.py** by DSS-Extensions (OpenDSS by EPRI): Python bindings for OpenDSS distribution system simulator. Used for feeder-level hosting capacity studies. (access: open; tracks: 2; id: opendssdirect) https://github.com/dss-extensions/OpenDSSDirect.py
- **GridLAB-D** by PNNL: Distribution system and end-use load simulator from PNNL, including responsive loads and markets. (access: open; tracks: 2,4; id: gridlab-d) https://github.com/gridlab-d/gridlab-d
- **PyPSA** by PyPSA team: Python power system optimization: capacity expansion, unit commitment and power flow. (access: open; tracks: 2; id: pypsa) https://github.com/PyPSA/PyPSA
- **PyPSA-USA** by PyPSA-USA contributors: Open US power system model built on PyPSA with EIA and other public data. (access: open; tracks: 2; id: pypsa-usa) https://github.com/PyPSA/pypsa-usa
- **GridSFM: small foundation models for the power grid (Microsoft Research)** by Microsoft Research: Microsoft Research framework for small foundation models in grid optimization, starting with AC optimal power flow. Learns from graph representations of topology, load, dispatch, flows and voltages across many scenarios. Open checkpoint (GridSFM_Open), datasets on Hugging Face, and an open-data pipeline from OpenStreetMap to solved OPF cases. Suited to fast screening (contingencies, planning scenarios, new data center load) and to giving exact solvers a starting point, not replacing them. MIT. (access: open; tracks: 2; id: microsoft-gridsfm) https://github.com/microsoft/GridSFM
- **ANDES: power system transient dynamics in Python (CURENT)** by CURENT (Hantao Cui et al.): Python library for phasor-domain transient stability simulation with symbolic model definitions, including inverter-based resource models. See the repo for license. (access: open; tracks: 2,4; id: andes) https://github.com/CURENT/andes
- **Generic EMT Modeling of Data Center Load (Dartmouth)** by Xingyu Zhao, Yingyi Tang, Junbo Zhao (Dartmouth): Modular electromagnetic transient model of a data center fed by a centralized UPS: rectifier, inverter, battery DC-DC, PFC, buck and VFD modules at three fidelity levels, IT load profiles and voltage ride-through control. Needs PSCAD 5.0.2 (commercial). No license file in the repo; ask the authors before reusing code. (access: mixed; tracks: 2,3; id: dc-emt-model) https://github.com/xingyuz-phd/Generic-EMT-Modeling-of-Data-Center-Load
- **OpenIBR: open-source grid-forming controls** by Heron Power: Universal grid-forming controller for inverter-based resources and large electronic loads such as data centers, aligned with IEEE 2800 and UNIFI. v1.1 builds IEEE/CIGRE TB958 DLLs from the open C code for PSCAD and similar tools, with debug outputs and a COMTRADE-logging test environment. Code: github.com/HeronPower/OpenIBR; DLL guide: github.com/HeronPower/OpenIBR/blob/dev/documentation/9_using_the_ieee_cigre_dll.md (access: open; tracks: 2,3; id: openibr) https://www.openibr.org/
- **HELICS co-simulation framework** by US DOE Grid Modernization Lab Consortium (PNNL, LLNL, NREL): Couples separate simulators (grid, buildings, markets, comms) into one time-synchronized federation. Python bindings. Simulates nothing on its own. BSD-3. (access: open; tracks: 2,3,4; id: helics) https://github.com/GMLC-TDC/HELICS
- **Grid2Op (RTE France)** by RTE France, hosted by LF Energy: Power grid operation environment for RL and agents, used in the L2RPN competitions. Agents act on topology and redispatch. (access: open; id: grid2op) https://github.com/Grid2op/grid2op
- **PGLib-OPF** by IEEE PES Task Force on OPF benchmarks: Standard benchmark library of optimal power flow test cases from 3 to 30,000 buses. (access: open; id: pglib-opf) https://github.com/power-grid-lib/pglib-opf

## Planning, siting and capacity expansion

- **GenX capacity expansion model (MIT, Princeton)** by MIT and Princeton (GenX team): Julia model that chooses which generation, storage and transmission to build and how to operate it, for low-carbon power system studies. GPL-2.0. Needs Julia and a solver. (access: open; tracks: 2; id: genx) https://github.com/GenXProject/GenX.jl
- **Manta: open energy system modelling platform** by Open Energy Transition: Open-source application for energy system modelling with graphical no-code workflows and full customization; plug-ins for PyPSA, GenX, Sienna and other frameworks; runs in the cloud, locally or on-premise; AI-assisted setup, debugging and results exploration. Code: github.com/manta-plan/manta (Apache-2.0). Launched 2026; public roadmap and beta program. (access: open; tracks: 2; id: manta) https://manta-plan.org/
- **REopt (NREL, now NLR)** by NREL (now NLR): Optimizes the size and dispatch of on-site solar, storage and generators for a site's load and tariff. Julia package and web API. (access: open; tracks: 1,3; id: nrel-reopt) https://github.com/NREL/REopt.jl
- **System Advisor Model (SAM, NREL, now NLR)** by NREL (now NLR): Performance and financial models for solar, wind, storage and other systems. Python access through PySAM. (access: open; tracks: 1,3; id: nrel-sam) https://sam.nlr.gov/
- **reV (Renewable Energy Potential model, NREL, now NLR)** by NREL (now NLR): Geospatial model of renewable generation potential, supply curves and siting exclusions. (access: open; tracks: 1; id: nrel-rev) https://github.com/NREL/reV
- **EVI-X toolbox (NREL, now NLR)** by NREL (now NLR): Models for EV charging demand and infrastructure needs (EVI-Pro family), with web versions. (access: open; tracks: 1,3; id: evi-x-toolbox) https://afdc.energy.gov/evi-x-toolbox
- **NEPA MCP Toolkit (PermitAI, PNNL)** by Pacific Northwest National Laboratory (PNNL): 23 Model Context Protocol servers that give AI agents federal environmental data for siting, NEPA review and permitting: permitting schedules, protected areas, species and critical habitat, wetlands, flood hazards, soils, air quality, cultural resources, Tribal lands, demographics, brownfields and federal regulations. pip install nepa-mcp; code at github.com/pnnl/nepa-mcp. Census and EPA AQS servers need free API keys. (access: mixed; tracks: 1; id: nepa-mcp) https://pnnl.github.io/nepa-mcp/

- **Kepler (Kubernetes power exporter)** by Sustainable Computing community (CNCF): Exports estimated power use per Kubernetes pod and container as Prometheus metrics. (access: open; tracks: 3; id: kepler) https://github.com/sustainable-computing-io/kepler
- **Scaphandre** by Hubblo: Rust agent reporting host and VM power, exporting to Prometheus, JSON and others. Early-stage. Apache-2.0. (access: open; tracks: 3; id: scaphandre) https://github.com/hubblo-org/scaphandre
- **PowerAPI** by Inria and University of Lille: Python framework for software-defined power meters down to process level. Estimates, not physical metering. BSD-3. (access: open; tracks: 3; id: powerapi) https://powerapi.org/
- **Carbon Aware SDK (Green Software Foundation)** by Green Software Foundation: Web API and CLI that wrap carbon intensity providers and return the best time and location to run a workload. (access: open; tracks: 3,4; id: carbon-aware-sdk) https://github.com/Green-Software-Foundation/carbon-aware-sdk
- **EnergyPlus (now under NatLabRockies)** by US DOE, NREL (now NLR): Whole-building energy and HVAC simulation with Python API. Needs facility inputs; not a calibrated data center model out of the box. (access: open; tracks: 1,3; id: energyplus) https://github.com/NatLabRockies/EnergyPlus
- **Coral NPU (Google)** by Google: Open machine learning accelerator core designed for energy-efficient AI at the edge. Hardware design, Apache-2.0. (access: open; tracks: 3,4; id: coral-npu) https://github.com/google-coral/coralnpu

## Load management, storage and flexibility

- **flex-pse: industrial energy flexibility optimization (Stanford)** by Stanford: Stanford open-source Pyomo/IDAES toolbox: model a facility as a time-discretized optimization, fit it from plant data, and schedule it against real electricity tariffs and demand response signals. pip install flex-pse. Apache-2.0. Community Slack: https://join.slack.com/t/flex-pse/shared_invite/zt-4b2va6ztg-K74JiAdHsmqY2CoGjbOmIQ (access: open; tracks: 3,4; id: flex-pse) https://github.com/flex-pse/flex-pse
- **NRGISE Open: local energy system simulator** by Fraunhofer ISE (Tobias Rohrer, Nils Reiners, Ricarda Hogl): Python time-step simulation of local energy systems (PV, storage, loads) with control strategies: peak shaving, self-consumption, controller benchmarking, forecast-error studies, batch sweeps. pip install nrgise. CC BY-NC-SA 4.0 (non-commercial). (access: open; tracks: 3; id: nrgise-open) https://github.com/nrgise-open/nrgise-open
- **Flexible BESS dispatch and arbitrage optimizer under grid constraints** by Mohammadreza Refaei: Optimizes battery charging and discharging across market prices while respecting hourly non-firm grid export limits and degradation cost. Example data from the German market. No clear license in the repo; ask before reusing code. (access: open; tracks: 3,2; id: bess-flexible-dispatch) https://github.com/Mohammadrezarefaei/bess-flexible-dispatch-optimizer
- **CityLearn** by Intelligent Environments Lab (UT Austin), hosted by LF Energy: Gym environment for coordinated demand response of many buildings with storage and solar. (access: open; tracks: 4; id: citylearn) https://github.com/intelligent-environments-lab/CityLearn
- **NILMTK: Non-Intrusive Load Monitoring Toolkit** by NILMTK community: Toolkit to disaggregate a whole-building meter into appliance loads, with loaders for public datasets including the US REDD dataset. Apache-2.0. (access: open; tracks: 3; id: nilmtk) https://github.com/nilmtk/nilmtk
- **OpenEAC Alliance M&V methodologies** by OpenEAC Alliance (repo maintained by WattCarbon): Open, peer-reviewed measurement and verification (M&V) methodologies for issuing Energy Attribute Certificates (EACs) per watt-hour or gram CO2e from battery storage, electrification, demand response and energy efficiency projects. Methods and statuses at methods.openeac.org; drafts go through a 30-day public comment period. (access: open; tracks: 3,4; id: open-eac-alliance) https://github.com/wattcarbon/open-eac-alliance

## RSI and agent loops

- **AIDE (Weco AI)** by Weco AI: Agent that iterates on ML code with a tree search over solutions, scored by a user-defined metric. (access: open; id: aideml) https://github.com/WecoAI/aideml
- **autoresearch (Andrej Karpathy)** by Andrej Karpathy: Minimal loop where an agent edits a training script, runs a short experiment, and keeps changes that improve a validation metric. (access: open; id: autoresearch) https://github.com/karpathy/autoresearch
- **OpenEvolve** by Asankhaya Sharma: Open-source implementation of the AlphaEvolve pattern: an LLM mutates programs and an evaluator scores them across generations. (access: open; id: openevolve) https://github.com/codelion/openevolve
- **ShinkaEvolve (Sakana AI)** by Sakana AI: Sample-efficient LLM-driven program evolution framework with novelty filtering and an archive of solutions. (access: open; id: shinkaevolve) https://github.com/SakanaAI/ShinkaEvolve
- **Darwin Godel Machine** by Jenny Zhang et al. (UBC, Sakana AI): Coding agent that edits its own code and keeps an archive of agent variants, scored on coding benchmarks. (access: open; id: dgm) https://github.com/jennyzzt/dgm
- **FunSearch (Google DeepMind)** by Google DeepMind: LLM proposes programs, an automated evaluator scores them, best programs are fed back. Released code for the Nature 2023 paper. (access: open; id: funsearch) https://github.com/google-deepmind/funsearch
- **DSPy** by Stanford NLP: Framework that optimizes LLM prompts and pipelines against a metric instead of hand-written prompts. (access: open; id: dspy) https://github.com/stanfordnlp/dspy
- **GEPA** by Lakshya A. Agrawal et al.: Reflective prompt evolution: an LLM reads execution traces and rewrites prompts, keeping a Pareto set of candidates. (access: open; id: gepa) https://github.com/gepa-ai/gepa
- **The AI Scientist (Sakana AI)** by Sakana AI: End-to-end loop that generates research ideas, runs experiments from templates and writes papers. (access: open; id: ai-scientist) https://github.com/SakanaAI/AI-Scientist
- **MLE-bench (OpenAI)** by OpenAI: 75 Kaggle competitions used to measure how well agents do ML engineering. (access: open; id: mle-bench) https://github.com/openai/mle-bench
